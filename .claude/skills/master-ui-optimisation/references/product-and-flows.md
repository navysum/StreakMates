# Product Thinking and Flow Reference

## User Intent
Start from the task, not from a component.

## Flow
Map entry → action → result → recovery.

## Screen Responsibility
Most screens need one dominant job.

## Progressive Disclosure
High-frequency actions stay explicit; low-frequency detail can move to tooltips, menus, drawers, and sheets.

## Invisible UI
Hidden states/components are part of the product:
- tooltip
- popover
- toast
- loading
- validation
- confirmation
- onboarding cue

## Onboarding
Teach progressively, in context, toward the user's first successful outcome.

## System Consistency
Reuse tokens and patterns to build familiarity, but bend the system deliberately when a unique context requires it.

## Conventions
Familiar patterns reduce learning cost. Novel interactions need a strong reason.
